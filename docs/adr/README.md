# Architecture Decision Records

Use an ADR before implementing a decision that changes an approved persistent model, state machine, public/private boundary, provider contract or architecture invariant.

Minimum ADR fields:

- status and date;
- context and source conflict/gap;
- decision;
- alternatives considered;
- security/privacy/legal impact;
- schema/migration impact;
- test impact;
- rollback/compatibility impact;
- approvals required.

Known future ADR candidates are tracked in `docs/architecture/IMPLEMENTATION-LEDGER.md`. A candidate is not an approved decision.
